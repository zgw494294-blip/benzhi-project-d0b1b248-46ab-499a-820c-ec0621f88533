# 数据持久化与恢复

数据目录包含 `state.json` 快照和 `journal.ndjson` 事务日志。事务先完整追加日志并执行 `fsync`，再以内嵌校验摘要的临时快照执行 `fsync`、回读验证和原子 `rename`。

启动时先验证快照摘要，再读取快照序号之后的日志。日志末尾不完整的一行会被截断并通过健康接口报告 `degraded`；序号跳跃、事务摘要错误、状态摘要错误或审计哈希断裂会拒绝启动，避免在来源不可信时继续出具结论。

恢复步骤：

1. 停止服务，完整保留当前数据目录。
2. 将经过验证的 `state.json`、`journal.ndjson` 和可选的 `.previous` 文件放入新的空目录。
3. 使用新目录和一个未占用的回环高位端口启动服务。
4. 请求 `/api/v1/healthz`，确认 `audit_valid=true` 且状态不是 `unhealthy`。
5. 导出一个已知案件包，核对对象标识、规则版本和摘要后再恢复业务流量。

不要手工编辑快照或日志。需要归档时应在服务停止且文件已同步后复制整个数据目录。
